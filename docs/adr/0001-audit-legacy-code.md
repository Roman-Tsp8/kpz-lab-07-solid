# ADR-0001: Аудит legacy-коду (Варіант 8 — Логістика та вантажоперевезення)

- **Статус:** Прийнято
- **Дата:** 2026-10-28

## Контекст
`LegacyLogisticsProcessor.processShipmentConsole()` — один метод (~45 рядків), який одночасно:
читає консоль, конструює `Sender/Cargo/Shipment`, рахує тариф (`if/else if` за рядком типу доставки),
рахує страховку, змінює статус, форматує накладну, «зберігає» у реєстр і «надсилає» email.

## Виявлені проблеми
| # | Проблема | Де | Порушений принцип |
|---|----------|----|-------------------|
| 1 | Anemic Domain Model: 15 публічних полів у `Sender`/`Cargo`/`Shipment`, жодного методу | `Sender`, `Cargo`, `Shipment` | Інкапсуляція, Information Expert |
| 2 | Порожні об'єкти заповнюються ззовні покроково; можна вага = -5, email = null | `processShipmentConsole` | Creator (валідний стан) |
| 3 | Бізнес-розрахунок (`baseRatePerKg`, множники 1.8/1.2, 0.5%) у UI-методі | рядки розрахунку | Information Expert, High Cohesion |
| 4 | `if/else if` за рядком `deliveryType` (+ магічні числа) | тариф | Polymorphism, Protected Variations |
| 5 | «Bloated Controller / Monolithic Main»: ввід + логіка + збереження + email в одному методі (7 відповідальностей) | весь метод | Controller, Pure Fabrication |
| 6 | Деметра: `shipment.cargo.deliveryType`, `shipment.sender.email` (навігація ланцюжками) | розрахунки, накладна | Law of Demeter |
| 7 | `deliveryType` лежить у `Cargo`, а не належить вантажу — це властивість послуги; `Shipment.totalCost` зберігається окремо й може розійтись із складовими | моделі | Information Expert |
| 8 | Жорстко зашиті дані (id=55, вага=120, вартість=50000, трекінг=770099): користувач їх не може задати | метод | — |
| 9 | Невідомий тип доставки мовчки трактується як Standard (немає ні `else`, ні помилки) | тариф | Валідність стану |

## Рішення
Перейти до Rich Domain Model + шарова архітектура (ui → application → domain; infrastructure реалізує порти).
Деталі рішень — ADR-0002…0004.

## Наслідки
(+) Кожен клас має одну причину для змін; (+) новий тип доставки не змінює існуючий код;
(−) більше класів/файлів (≈30 замість 4) — свідомий компроміс заради тестованості й зміни.
